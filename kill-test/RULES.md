# Rules for the coder (KT-30 to KT-107)

The first 48 rows, KT-30 to KT-77, are the small fill-ins the four notes need before code. Approving a note approved its rows, and all four notes were approved as written on 25 Oct 2026. Rows KT-78 to KT-91 (section 5) are readings made while coding Week 1, approved as written on 28 Oct 2026. Rows KT-92 to KT-107 (section 6) are readings made while coding Week 2, proposed for approval. None adds to the tuned list of KILL_TEST section 7 (KT-19 to KT-29). Two rows go beyond a plain reading, and each was named in its note for approval: KT-47 sets aside a frozen cost target ([note 2](design-notes/2-drive.md)), and KT-53 reads the fit test slightly more strictly than its plain wording ([note 3](design-notes/3-tower.md)). The rows live here in the kill-test folder, beside the frozen charter, which stays untouched. Every constant in the code cites its row (FORBIDDEN 28).

## 1. Object generator (KT-30 to KT-43)

| Row | Rule |
|---|---|
| KT-30 | Teaching pairs. The family key draws kind 1's pair of moved core traits from the 6 possible pairs, then kind 2's from the other 5, each uniformly. The two pairs may share a trait. |
| KT-31 | Keys. The set key is 32 bytes. For the tuning set it is the committed 64-character hex tuning key, decoded to its 32 bytes. For a kill-run set it is the SHA-256 of the 64 lowercase hex characters that Bitcoin Core shows for block N + 6's hash, with no newline. It is read once that block has 6 confirmations (5 blocks on top). Family key = HMAC-SHA256(set key, the text "family/" and the family number). Run key = HMAC-SHA256(family key, the text "run/" and the run number). Each stream's key is the first 128 bits of HMAC-SHA256(its family or run key, stream name). The generator is NumPy's Philox, checked against the published test vectors (W37). |
| KT-32 | Draw numbers. Every object's place and every kind's place has its own try count. Try n uses its own counter values, so a redraw never changes another place's random numbers. In a cascade, each affected place moves to its next unused try. A far apple's or h2's count of 10,000 failed tries starts again after each cascade. |
| KT-33 | Noise addressing. Each reading's noise is looked up by the replica key, the item's fixed place in the run plan and the trait, never by role, kind or nature. The main line uses replica key 0. SOUR's h2 and the SWEET-CONTROL apple share h2's place, and each Q probe has one place across its S8, SOUR and SWEET-CONTROL copies. Each P check copy's key is set by its checkpoint and probe, the same for every mind. Taste readings use the eaten item's place. In W37's key record (stream_keys), the tick field holds the place and the creature field is 0 for every mind. |
| KT-34 | Noise shape. Gaussian noise with standard deviation 0.01 of range, made from two keyed uniform draws (Box-Muller), so each reading always uses the same counter values. The laptop-to-cloud replay test (I05) must still match bit for bit. Readings are clipped to 0 to 1. |
| KT-35 | One look per decision. Each decision gets one noisy reading per visible trait. The verdict after eating and the memory write reuse that reading. Taste is read once, at the real eat, with the same 1% noise. |
| KT-36 | Certificates judge true generated values, never noisy readings. |
| KT-37 | A value on a core trait is drawn uniformly inside its 0.05 band. |
| KT-38 | Separation from tuning. A kill-run check kind counts as "in the tuning set" only if its whole kind record (core traits, bands, free ranges) matches a tuning kind exactly. In practice this almost never fails, so the certificate's real work is its second check: every check kind was drawn from its own set's key. The charter's 10-noise-width "never seen" rule (W36) is the untested alternative I did not pick. |
| KT-39 | Warm-up kind check. "Within 10 noise widths" means a gap under 0.10 between band edges, overlap included. It counts only on H's core traits where the warm-up kind has a core band of its own. A failing kind is swapped, for that run, for the run key's next kind draw. The swap still comes from 4 different tuning families, never H's own, and is logged. |
| KT-40 | Which item models what. Far apples 1 to 4 are P's first 4 far apples in draw order. They model the far-half look-alikes of pairs c1c2, c3c4, c1c4 and c2c3 in turn. Q's h2 look-alikes use the same pair order. The h1-half look-alikes in P and Q use c1c2, c3c4, c1c3 and c2c4. P's 2 neutrals are one item each from neutral kinds 1 and 2, and Q's from kinds 3 and 4. |
| KT-41 | Every keyed choice among listed options is uniform. That covers which 4 tuning families and kinds the warm-up uses, the labels c1 to c4, the band side when both fit, and the warm-up order. It also covers section 6's trait order, which is one shuffle of all 22 traits per run. |
| KT-42 | Power-check families. Simulated set s, place i uses practice family 1,000 + (s − 1) × 120 + i, so a bigger set keeps the smaller set's families. In KT-15's placement rule, i is this place, not the practice-family number. "Core-trait placement" copies only which 4 traits are core; everything else is drawn fresh. Generator tests use practice families 200,001 and up. |
| KT-43 | Readings of loose wording. A neutral's surface distance is within 0.9 to 1.1 times the mean for P's far apples. All 30 tuning families come from the tuning key; the bench uses no development-vault family. Exact hue follows KT-01. The other 6 detail traits are independent numbers from 0 to 1, drawn like any other trait, so the 4 smell channels need not sum to 1. W15's names are only labels. The plain-words line that the teaching apples "look very different from each other" adds no certificate: a2 to a4 are ordinary apple draws. |

## 2. Drive (KT-44 to KT-50)

| Row | Rule |
|---|---|
| KT-44 | The drive is written twice from section 5: once inside B1n-mind, frozen with the bots in Week 2, and once in the mind package in Week 3. A test outside both packages feeds both copies the same grid of inputs (share, reliability, energy, thinking cost, R, b, verdict state). It requires identical chances, choices and no-safe-option flags at every freeze. B1n-mind's nearest-item lookup follows KT-05's bot rules: observable traits only, in noise widths, stored at the eat, ties to the most recent item. |
| KT-45 | One check (B14) is one candidate's fit on one trait, or for B1n-mind one stored item on one trait. It is counted once per decision, when that test first switches on, and again for a candidate that an objection reset brings back. |
| KT-46 | Who pays. K-F, TW2, OS10 and K-F-NOWARM pay the per-spike cost for every spike, "unknown" included. TW7, capped OS01 and B1n-mind pay 0.001 per check (KT-45), and free OS01 pays no thinking cost. Every tower mind and B1n-mind pay 0.03 per object for the sharp look. Bots pay nothing. The verdict after eating is free. The drive's sharp-look rule (M36, PLACEHOLDER-33) never runs on the bench, since every object is seen sharply. A less-reliable mark acts only through eat's chance. |
| KT-47 | The per-spike cost (KT-27) is set after KT-19 to KT-26. It makes K-F's median thinking cost per decision on the tuning set equal the median of 0.001 × checks for the same decisions. The "10 to 30% of spending" target in PLACEHOLDER-19 and M42 does not apply on the bench, and B14's 0.001 is used as section 4 states, untuned. |
| KT-48 | Energy order. The reset to R + 10 comes first (on warm-up and teaching tastes, before the look), then the 0.03 look, then thinking. Each cost is taken off once. The thinking cost is the spike or check count times its cost, summed exactly. It is charged at the moment of choice, rounded to the nearest whole milli-unit, halves rounded up. Skip's test compares the energy left with R. No B12 cost (basal, movement or eating) and no B13 holding cost applies on the bench. R is drawn in whole milli-units. |
| KT-49 | Drive trace. Every decision logs eat's chance (when a kind is named), skip's chance and the pick the drive would make. On a forced taste the eat is then forced. The untried-value tally (PLACEHOLDER-34) is computed and logged. The mind never reads this trace. The chooser's own list still records each option's order, chance and cleared_bar, so FORBIDDEN 13's fallback test can run. Habits are off and there are no proposals, so ordinary bench choices carry the source "bench" in the per-run files (section 11). The fallback and designed-exposure tags keep their glossary meanings. Each tower mind's version record lists OS07 (habits off, lifetime), and OS01 and OS10 add their own switch. |
| KT-50 | In the no-safe-option fallback, equal chances mean skip. A named kind with no eats on record cannot arise. If it ever did, the code stops with an error rather than invent a starting chance (FORBIDDEN 8). |

## 3. Tower (KT-51 to KT-69)

| Row | Rule |
|---|---|
| KT-51 | Layer timetable: one settling step per layer. Context switches on at step 1, object at step 2, parts at step 3 and details at step 4. Once on, a layer stays on for the rest of the decision, after resets too. The verdict after eating uses the same timetable. |
| KT-52 | Elimination. At the ends of steps 1, 2 and 3, any candidate trailing the leader by at least the commit margin (KT-24) is eliminated. It is held at rest, with no input, no spikes and no push-down, and is logged in elimination_events. "Unknown" is never eliminated and never counts as the leader here. Candidates a reset brings back are not eliminated again in that decision. |
| KT-53 | Fit through the detectors. Each trait has 16 detectors, centred at (k + 0.5)/16 of its range for k = 0 to 15. A detector is lit when the reading lies within one detector width (KT-23) of its centre. A trait fits a candidate when a lit detector's centre lies inside the candidate's stored range. Each fitting checked trait adds its relevance weight to the candidate's steady input. This can be up to 1/16 of range stricter than section 8's exact scoring test, which slightly hurts K-F. |
| KT-54 | Attention. For parts and details, each trait's pooled weight is the average of the surviving candidates' weights on it. Each candidate counts in proportion to its activation at the end of the previous step, or equally if all are 0. "Unknown" takes no part. The 3 highest are checked, ties broken by the run's trait order (KT-41). The set is chosen once, when the layer opens, and kept after resets. Before an eat, only visible traits are eligible. Context and object read all their traits. |
| KT-55 | Exact hue is an ordinary detail trait for the mind: stored, checked and blamed like any other. KT-01's "never checked against one" is a generator rule. |
| KT-56 | Objection. Only parts and details object. The leader is the active group, "unknown" included, with the highest activation; if two tie, no group leads at that step. A layer's mismatch is the sum of the leader's weights on that layer's checked traits that do not fit it. An objection fires when the same candidate leads, with mismatch in the same layer at or above the objection threshold (KT-25), at the ends of 2 steps in a row. A leading "unknown" is never objected to. Mismatch never enters an option's value or the bar, which is how FORBIDDEN 5's check is read. |
| KT-57 | Knock-down. On a decision's 1st and 2nd objection, the leader's neurons and trace go to rest, every eliminated candidate returns at rest, and the race reopens. Each is a reset under PLACEHOLDER-13. A later objection removes that leader for the rest of the decision and returns no one, so it is not a reset. |
| KT-58 | "Unknown" is a group of 8 neurons with steady input equal to the new-kind threshold (KT-26) from step 1, staggered like any group. It pushes and is pushed like any candidate. It has no ranges or weights, takes no part in attention, and is never eliminated or objected to. |
| KT-59 | Push-down. Each spike in a group lowers the charge of every neuron in every other active group by the inhibition strength (KT-22), in the next 1 ms substep. Charge may fall below rest and leaks back. There is no push-down within a group. |
| KT-60 | Neuron update, every 1 ms substep: charge decays toward rest by the leak (KT-19), then adds the neuron's input. At the threshold (KT-20) the neuron spikes, resets to rest and ignores input for the refractory period (KT-21). |
| KT-61 | Staggered shares. Neuron k (0 to 7) of a group gets (2k + 1)/8 of the group's input. So the shares run from 1/8 to 15/8 and average 1. No tuned number is added. |
| KT-62 | Activation. A group's trace adds 1 for each spike of any of its neurons and decays by e^(−1/10) per substep (KT-09's 10 ms). Every rule reads it at the end of a step. |
| KT-63 | Leading and holds. A leads B by the margin when A's activation minus B's is at least the commit margin (KT-24). During the hold, "stays the leader" means strictly the highest activation, so a tie breaks the hold. At each step's end: objections first, then elimination (handover steps only), then wins, holds and the step-30 rule. |
| KT-64 | A hold still running at step 30 runs on to its step s + 4 and settles if it survives. If it breaks in steps 31 to 34, the decision is unsettled. This is rare, and it slightly lowers K-F's settle rate (rule 1) compared with falling back to the step-30 test. The step-30 "unknown" test applies only when no hold is running at step 30. |
| KT-65 | Committed verdict. On the bench, a decision's committed verdict is its settled verdict, and "unknown" at step 30 counts as settled. An unsettled decision has no committed verdict and names no kind. So an unsettled h2 builds SWEET-CONTROL from h1's kind (KT-76), and memory treats it as "unknown" (KT-74). The report lists "unsettled" as a fourth outcome for h2's own verdict (section 10). |
| KT-66 | Verdict after eating: the same timetable and rules, from rest, for exactly 30 steps, on the decision's own reading (KT-35). Its details layer also reads all 4 taste traits, beside the up to 3 visible traits attention picks (section 6). Its logged verdict is a win settled by step 30; otherwise "unknown" if no candidate leads "unknown" by the margin at step 30; otherwise "unsettled". It changes no choice, record or right-or-wrong call. |
| KT-67 | OS01. Every visible trait of every candidate (and taste, after eating) switches on at step 1, with no elimination and no 3-trait limit. Parts and details still object, each over all its traits. Capped OS01 makes its checks one trait at a time in the run's trait order, over every candidate. It stops before the trait that would pass its limit. The limit is the median thinking spend of that run's 210 K-F decisions, counting thinking only. So K-F runs first on each run key. |
| KT-68 | TW7. Each group is one rate unit updated every 1 ms substep, so staggering does not apply. It moves toward gain (KT-28) times its input above the firing level, minus push-down equal to what K-F's spikes would give at those rates, with time constant KT-29. The firing level is the threshold (KT-20) times the leak (KT-19). TW7's activation stands for the group's expected spike trace, so K-F's commit margin and thresholds apply unchanged. Everything else is reused from K-F. |
| KT-69 | Extra logging, outside the mind. Each decision's log says whether, at its last step, the leader and a runner-up within the margin are both in the H set. The harness works this out from the lineage log (FORBIDDEN 18). It also logs the step at which each verdict settles, so the report can give the share of "unknown" verdicts settling before step 7. |

## 4. Memory rule (KT-70 to KT-77)

| Row | Rule |
|---|---|
| KT-70 | Match and eat records. An eat's outcome is the energy the item gives as it lands: +15, 0 or −20. The look and thinking costs are not part of it. Its class is gain (above 0), nothing (exactly 0) or loss (below 0). A guess is right when its class equals that of the eat that founded the named kind, and a confirmed win (PLACEHOLDER-07) uses the same test. Each eat on record stores its class and a yes or no for "energy at or above R right after the eat". This holds in every tower mind. |
| KT-71 | The line. A trait is "varied" (loses 0.1 on a stretch) or "differing" (gains 0.2 on a split) only if it lies more than one detector width outside the stored range. That is PLACEHOLDER-03's exact line, not the tower's detector fit. TW2 uses the same line. |
| KT-72 | Split order. The +0.2 steps go on the guessed kind's differing traits in the blamed layer first (in any layer for TW2), capped at 1. Then the new kind copies the guessed kind's weights. TW2 uses the same order. A split child starts with reliability 1 and no confirmed wins. |
| KT-73 | Unexplained mistake. The eat and its outcome go on the guessed kind's record, and its count rises by 1. Its ranges and weights do not change. |
| KT-74 | No merges: no write merges two kinds on the bench. Every forced eat whose decision did not settle is written as an eat judged "unknown" (PLACEHOLDER-93), in warm-up, teaching, h2 and SWEET-CONTROL alike. |
| KT-75 | Forgetting and slots. Forgetting follows PLACEHOLDER-07 as written, even when it picks the kind the current verdict named. It happens after a split child has copied its parent and before the new kind takes its slot. A new kind takes the lowest free slot. Kinds with no confirmed win tie on "last confirmed win", so the lowest slot number decides. |
| KT-76 | h1's kind is the kind memory files h1's eat under: the new kind, the stretched kind, the split child or the marked kind. It keeps that identity through later splits, because a parent keeps its identity. The harness, never the mind, computes the H set from the lineage log (FORBIDDEN 18). |
| KT-77 | Small readings. Ranges are stored as the value plus or minus one detector width, not clipped. The outermost layer is the whole context layer, scene and host. OS10 stores no taste at all: none in storage, stretch, blame or splits. TW2 keeps reliability 1. When no trait explains its mistake, TW2 still makes a new kind, treated as a split child. M10's "count" is the number of eats on the kind's record. |

## 5. Readings made while coding Week 1 (KT-78 to KT-91)

Proposed in the Week 1 pull request and approved as written on 28 Oct 2026. Writing the generator needed these fill-ins, which the frozen rules and rows KT-30 to KT-43 leave open. None changes a frozen rule or number, none is tuned, and none treats one mind differently from another. All are world-side and conventional unless marked.

| Row | Rule |
|---|---|
| KT-78 | Taste ranges, read as section 2 words them. H's 4 taste traits range over the full 0 to 1 and take no draw, and a look-alike kind copies H's ranges. A neutral kind's taste traits are free traits like any other: each gets a width from 0.6 to 1.0 and a place, drawn after the other free traits in trait order. (Section 13's short summary of KT-02, "taste has the full range", is read as being about H.) |
| KT-79 | Check kind numbers. Kinds 3 to 8 move c1c2, c3c4, c1c3, c2c4, c1c4 and c2c3 in turn, the order of M1, M2 and M3. |
| KT-80 | Streams. Every kind and object draw uses the stream named "world", from the family key for family draws and from the run key for run draws. Sensor noise uses the run key's stream "sensor_noise". |
| KT-81 | Counters. A Philox counter is four 64-bit words: (try number × 2^32 + block number), place, creature (always 0) and replica key. Try numbers start at 1. Each place is listed in `src/world/kinds.py` (family draws) and `src/world/run_plan.py` (run draws). One reading's noise for one trait uses the counter (trait number, place, 0, replica key): Box-Muller on its first two words, noise = 0.01 × √(−2 ln(1 − u1)) × cos(2π u2). So that it replays bit for bit on any machine (KT-34, I05), this is worked out in Python's decimal arithmetic at 40 significant digits, with ln and √ as the decimal module gives them, cos by a Taylor series after folding the angle into 0 to π/2, and π to 60 digits, then rounded once to a float. Every step uses one fixed decimal context, so no decimal setting made elsewhere in the process can change a reading. The platform's maths library is never used, since it may round log and cos differently from one machine to the next. |
| KT-82 | Turning words into draws. A uniform number is a word's top 53 bits divided by 2^53, so it lies in [0, 1). A value in a range is low + (high − low) × u. A choice among n options is the integer part of u × n. A shuffle is Fisher-Yates from the last position down. Picks without replacement take an index into what is left. R is 20,000 + a choice among 40,001 milli-units. |
| KT-83 | Order of draws within one try. A kind: its 4 core traits, then each core band's centre in trait order, then each free range in trait order (width, then position). A look-alike kind: for each moved trait in trait order, the gap and then the side. An object: each trait in trait order except exact hue, skipping traits set from outside (scene and host), then the hue offset. A look-alike object draws no hue offset. A family: H (place 1), the labels c1 to c4 as a shuffle of H's core traits (place 2), the two teaching pairs (place 3). |
| KT-84 | Warm-up slots. The 4 warm-up kinds are drawn in the order nourishing, poison, nothing, nothing. Each slot's tuning family is a uniform choice among the tuning families not yet used and not H's own, then its kind within that family, then its scene and host. A KT-39 swap is that slot's next try, all four draws anew. A warm-up poison item's model is a fresh member of that tuning family's H, with its own drawn scene and host; it is never shown. |
| KT-85 | Neutral replacement. The 1,000-draw count of a neutral item starts again when its kind is replaced and after a cascade. The replacement is that neutral kind's next try under the family key (try 2, 3 and so on) and stays in use for the rest of the run, cascades included. Warm-up kinds never meet the 1,000-draw rule, since a warm-up item has no item-level certificate. |
| KT-86 | Cascades. A cascade moves every place from P's first look-alike modelled on h1 onward to its next try, including items that can never fail. Every 10th cascade in a run does the same from h1 onward, so the warm-up kinds and items, a2 to a4 and the teaching look-alikes are drawn again too. R, b, the trait order and the warm-up order are drawn once per run and never again. |
| KT-87 | Replica keys and probe order. The main line is 0. A P copy at checkpoint c (1, 2, 4, 6 or 8) on probe i (1 to 20) is 1,000 × c + i, and Q probe i is 9,000 + i. Both sour-apple branches use 0, since h2's place is used nowhere else. P's probes are far apples 1 to 8, the look-alikes on h1, the look-alikes on far apples 1 to 4, the 2 neutrals and the 2 copies. Q's are the 4 apples near h1, the 4 near h2, the look-alikes on h1, the look-alikes on h2, the 2 neutrals and the 2 copies. |
| KT-88 | A failed separation certificate (KT-38) stops generation with an error. Nothing is redrawn, and that set cannot be used. |
| KT-89 | The import guard (I02) reads "anything but NumPy and Numba" strictly: the mind may not import the standard library either, except `from __future__`. Inside the mind package, a module imports another by its full name (`mind.x`); relative imports are refused, because mind code could aim them elsewhere by setting `__package__`. The guard also refuses these forms, which would let an import hide from it: any use of `__import__` or `importlib`, and of the built-ins `exec`, `eval`, `compile`, `globals`, `vars`, `locals`, `getattr`, `setattr`, `delattr`, `help` and `breakpoint`; any dunder name except `__all__`, `__doc__`, `__version__`, `__slots__` and `__debug__`, and the attributes that reach loaded modules, a module's globals or a frame (`modules`, `meta_path`, `__globals__`, `__dict__`, `f_globals` and the like), whether used, imported, imported under another name or written as a string; a name imported from NumPy or Numba that is itself a module from outside them; any import of their private, test, build or `__main__` modules (`f2py`, `ctypeslib`, `testing`), in either `import` or `from` form, and any private attribute (`._x`) reached from a name bound to NumPy, Numba or something imported from them; a file it cannot parse; a source encoding other than UTF-8; any symlink in the package; and any file Python could import but the guard cannot read (.so, .pyd, .dll, .pyw, .pth, .zip, .egg, upper-case suffixes, and any .pyc that is not Python's own timestamp cache of a source file beside it, holding that source's code). It never runs mind code, and it looks NumPy's modules up in a separate interpreter. It is a static check against the forms listed: it cannot see every route Python's reflection allows, such as a module reached through a chain of attributes. Keeping minds away from the world's objects at run time is the harness's job (Week 2). |
| KT-90 | Safety stops (untested). A run that reaches 1,000 cascades (100 redraws of h1), or replaces one neutral kind 1,000 times, stops with an error instead of looping for ever. Neither has happened in testing; the redraw rules never need anything close. |
| KT-91 | Two numbers with no row of their own. Each family gets 10 runs per mind, as section 5's frozen text says. And when the checker re-checks a finished plan, it allows 10^−12 for float rounding at the edges of drawn bounds. The redraw rules compare exactly, as the frozen text words them. |

## 6. Readings made while coding Week 2 (KT-92 to KT-107)

Proposed in the Week 2 pull request, for Aitzaz's approval. Building the cafeteria harness, scoring, the bots, B1n-mind and the analysis script needed these fill-ins, which the frozen rules and rows KT-30 to KT-91 leave open. None changes a frozen rule or number, and none adds to the tuned list (KT-19 to KT-29). KT-101 registers the three radii that section 4 says are chosen on the tuning set. Rows that could change a verdict at the margin say so.

| Row | Rule |
|---|---|
| KT-92 | Costs in whole units. Energy is kept in whole milli-units and every cost in whole nano-units (a millionth of a milli-unit): the look is 30 milli, one check (B14) is 1,000,000 nano, and KT-27's per-spike cost is registered as a whole number of nano-units. A decision's thinking cost is its count times the unit cost, summed exactly, then rounded to the nearest milli-unit with halves rounded up (KT-48). The harness recomputes it from the mind's count and stops if the mind's own figure differs. |
| KT-93 | One interface for every mind. A mind is made by `make(config)` and answers `decide`, `land`, `write`, `dump` and `info` (B21). Everything crossing is plain data: numbers, text, lists and maps, never pickled objects, NaN or infinity. The bots and B1n-mind run inside the harness's process; the mind package, the twins and the stub run in a process of their own, which gets an empty working folder, an environment holding only a fixed hash seed, a copy of the package's `.py` files, and an audit hook that refuses imports other than NumPy, Numba and the package, any file write, any file outside those folders, and sockets, subprocesses, signals, `ctypes`, tracing and the like. This is the run-time half of FORBIDDEN 18 that the static import guard (KT-89) can't give. Both ways of hosting give identical answers, which a test checks. A test-only mind's own constants cite this row. |
| KT-94 | Memory dumps. A tower mind's `memory_state_dump` lists each candidate's slot, its 22 stored ranges, its 22 relevance weights in whole tenths from 0 to 10 (PLACEHOLDER-02's steps are tenths; M20's start is 5), its reliability and its number of eats. A candidate stores all 4 taste ranges or none. The harness reads dumps only to score (section 8) and never shows them to a mind. |
| KT-95 | A failure stops everything. A mind error, a broken interface check, a failed certificate or a generator stop ends the run and the script with an error. Nothing is dropped, skipped, retried or replaced, so a set's results are all of its runs or none. |
| KT-96 | A check copy ends at its committed choice. No outcome, taste, verdict after eating or memory write lands on a copy (glossary: committed eat or skip), and the copy is thrown away. |
| KT-97 | What a mind is told. At birth: R, b, its own settings and, for tower minds, the run's trait order (section 6). Before each decision: the 18 visible readings as a fresh read-only array and its energy after the reset and the look. After an eat: the outcome, the energy after it and the 4 taste readings. Nothing else: no label, role, nature, place, replica key, phase, schedule position or "forced" flag. A write event's trigger is the mind's own reading of its pick (a skipped decision that is then eaten was forced); the harness logs the true provenance. The schedule is fixed and public, so a bot that needs h1 or the teaching items finds them by counting its own eats: its 41st stored item is h1, and items 41 to 48 are t1 to t8. A bot rule that refers to an item not yet stored gives "eat", as X36 says of an empty memory; on the bench that happens only on forced tastes, so it changes only the log. |
| KT-98 | The H set, built as the run goes. The harness gives every candidate a lineage id that is never reused, translating the mind's slot numbers, which forgetting frees for reuse (KT-75).
